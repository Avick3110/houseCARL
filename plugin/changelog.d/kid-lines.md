- **`housecarl_layer` now reads KID's `_KID.ini` files as KID 4.0.6 and 4.1.0 do: `formids=` / `plugins=` list the KID lines naming those records (target, filter or keyword value, EditorID lines included), and `filter=` expands a file's lines with what KID does with each: a line it drops with no log (a type not one of its 19, spelt exactly), one it fails to parse and logs `Failed to parse entry` for (a FormID it cannot read, a chance that is not a number, a group line with an empty member), one it drops as it looks up the forms (an empty keyword, or a keyword FormID naming no keyword; every exact plain filter, or every `-` filter, failing; every `+` group losing a part; a group line keeping no keyword), a group line with no members section or no members, which KID ignores with a warning, a filter it skips, a keyword it creates, a filter name it keeps as text.** `distributor=["kid"]` lists KID's files; it was refused as "not read yet". With `distributor` omitted, the bare call now answers SkyPatcher's layer as before, then one summary line each for SPID and KID naming the call that lists their files (SPID's file list moved to `distributor=["spid"]`); with a selector or `filter=`, KID's part follows SPID's and takes what is left of `max_chars`, saying where it is cut. Calls that already read SPID take as long as before (on ARR about 10 s for a selector call, 2 to 3 s for the bare call); `distributor=["kid"]` alone takes about 0.3 s for its file list and about 8 s on ARR (5 s on a test order) once it resolves lines. The `kid-authoring` skill now teaches KID 4.1.0: files in byte order, `#` comments, no comment after a value, `+` groups that are alternatives, a type that is not one of the 19 dropped with no log, and four example lines whose trailing comments broke them are fixed. Check: `housecarl_layer distributor=["kid"] filter="<mod>"`.
